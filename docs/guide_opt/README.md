# LaxCode 引导页优化建议

评估日期：2026-10-28。依据当天在 https://laxcode.cn/ 的浏览器体验，以及当前仓库引导组件的阅读结果。

## 两个前端优化 demo 可参考

本目录提供两种引导页优化方式的独立前端 demo，可直接用浏览器打开，无需启动后端或安装依赖。

| 方案 | 可打开的 demo | 适用场景 |
| --- | --- | --- |
| A：任务入口优先（优先推荐） | [demo-task-first.html](./demo-task-first.html) | 用户已有任务，希望迅速理解价值并开始使用 |
| B：轻量三步引导 | [demo-guided.html](./demo-guided.html) | 用户第一次接触执行型 Agent，需要理解任务、执行、交付的关系 |

两个 demo 沿用本次体验后提出的视觉方案，展示页面层级与交互，不连接线上 API，不创建沙箱，不执行真实任务，不产生真实下载。示例结果为固定演示数据。

- **方案 A**：切换“分析数据 / 写个小工具 / 绘制流程图”，输入框和成果示例同步更新；支持编辑任务、模拟开始、查看示例成果和下载反馈。
- **方案 B**：选择任务后，逐步查看“选择任务 → 执行过程 → 获取成果”；最后可以重新体验。进度展示是手动演示，不代表真实执行状态。
- [src/demo-task-first.html](./src/demo-task-first.html)、[src/demo-guided.html](./src/demo-guided.html) 是可读的 HTML/CSS/JavaScript 片段源文件，供前端实现参考；根目录的同名 HTML 是已封装的浏览器入口。
- Demo 使用系统字体和内嵌资源，适配窄屏与系统明暗主题。它们是设计参考，正式产品仍需按现有 React 组件与 API 契约接入。

## 结论与目标

核心执行链路已经可用；需要优先改善的是“知道做什么 → 看见执行 → 找到成果 → 继续修改”的体验。

当前引导主要介绍功能和执行过程，新用户先看到长截图、命令、技能名和性能统计，成果价值出现较晚。优化目标是让第一次访问的用户快速回答三个问题：

1. LaxCode 可以帮我完成什么？
2. 我现在可以输入什么？
3. 完成后，我在哪里查看和下载结果？

## 已观察到的问题

| 问题 | 体验证据 | 优化方向 |
| --- | --- | --- |
| 首屏信息重过程、轻成果 | 云端编程和技能两屏使用多张长对话截图，首屏主要呈现工具命令，需继续滚动才能看到产物 | 用“一句需求 + 三步执行状态 + 一个成果卡片”替代长截图 |
| 首次引导重点分散 | 三屏中有一整屏介绍性能监控 | 性能监控放到首次任务结束后的可选提示或帮助入口 |
| 首次任务缺少具体入口 | 引导结束后是“从一个想法开始”和空输入框 | 提供能直接填入输入框的短任务示例 |
| Agent 不清楚产品下载方式 | 创建 hello.txt 后，回答表示无法确认页面下载入口，并建议查找项目文件列表 | 提供准确的产品交付说明，让回答引用真实产物卡片 |
| 文件成果发现成本高 | 普通文件隐藏在“本次新增 / 修改”列表中；图片有更直观的缩略图 | 少量成果默认展开，显示文件名、类型、预览、下载 |
| HTML 预览与用户预期不同 | 报告文件预览呈现 HTML 源码 | 区分“成品预览”和“源码”，CSV 使用表格视图 |
| 调试信息占用主界面 | 顶部 user_id / session_id、消息请求 ID、原始工具命令较突出 | 默认保留任务标题与状态，诊断信息放入“运行详情” |
| 会话和下载包命名缺少语义 | 会话采用“会话 01/02”，下载包显示“未命名会话” | 按任务自动生成短标题，下载包沿用标题 |

以上是单次体验发现，不等同于转化率结论；需要在真实新用户测试中验证改版收益。

## 方案 A：任务入口优先

参考：[demo-task-first.html](./demo-task-first.html)。

### 页面结构

1. 顶栏只保留品牌和轻量辅助入口。
2. 左侧给出价值主张、三种具体任务和可编辑的输入框。
3. 右侧展示完整的短示例：需求、执行状态、成果及预览/下载操作。
4. 底部用一行说明“描述任务 → 云端执行与验证 → 预览并下载”。

### 建议文案

> **说出想法，拿到能用的成果。**  
> 写代码、分析数据、绘制流程图。LaxCode 在你的独立云端工作区执行，完成后即可预览和下载。

主按钮使用“试运行这个示例”或“开始我的任务”。点击示例先填充任务，允许用户修改；实际提交应经过明确的发送动作，不能仅浏览示例就开始消耗资源。

选择示例时，输入内容和右侧成果类型需要同步，避免显示“绘图任务”却仍看到销售报表。正式接入时，示例必须包含足够的输入数据与明确输出格式，并与实际支持的能力一致。

### 取舍

优点是开始快、成果直接可见，也容易融入日常工作区空状态。需要避免把用户已经输入的内容无提示覆盖；有输入后切换示例，应保留草稿或明确提示替换。

## 方案 B：轻量三步引导

参考：[demo-guided.html](./demo-guided.html)。

| 步骤 | 用户看到什么 | 主要动作 |
| --- | --- | --- |
| 选择任务 | 分析数据、生成工具、绘制流程图，每个选项说明会得到什么 | 选一个任务，查看后续过程 |
| 查看执行 | 工作区准备、任务执行、结果验证；原始日志按需展开 | 理解 Agent 正在做什么 |
| 获取成果 | 文件卡片、预览、下载、继续修改 | 将选中的任务带入真实工作区 |

每步只传达一个概念，避免长截图和内层滚动。正式产品保留“跳过”“上一步”和最后的“开始我的任务”；关闭与跳过不应创建任务，允许从帮助入口重新查看。

Demo 为便于独立浏览，最后一步采用“重新体验示例”。正式接入应改为进入工作区，并明确这是示例讲解还是实际执行。引导里的模拟进度不能冒充真实沙箱状态。

该方案学习路径更明确，但比方案 A 多出点击成本。建议默认优先采用方案 A，方案 B 作为“第一次使用？看看如何工作”的可选教程；也可以分组试验两种入口。

## 视觉与内容规范

- **统一强调色**：延续品牌蓝青色系，主按钮、选中态、完成状态使用一致的色彩规则。减少当前引导墨绿、工作区橙色与品牌渐变之间的竞争。
- **优先展示成果**：示例中隐藏 UUID、时间戳和原始 bash 命令；保留一条简明执行摘要，展示实际能拿到的代码、报表或图片。
- **控制布局宽度**：桌面内容宽度约 1040–1160px；标题、说明、任务输入与成果卡形成清晰层级。移动端按单列排列，保持页面自然滚动。
- **减少重复容器**：统一卡片圆角、边框、阴影；避免截图外再包多层背景和边框。
- **使用具体语言**：“绘制流程图”优于“使用 Skill”；技能名放入辅助说明。默认将 token、LLM、tracing 等内容留在高级详情里。
- **保证可访问性**：按钮焦点清晰，可用键盘操作；触控目标约 44px；正文对比度达到 WCAG AA；重要信息不只靠颜色区分。
- **解释工作区持续性**：明确访客身份如何找回、文件保留多久、换设备如何继续。当前实际规则需产品方确认后再写入，不能在引导里承诺未实现的能力。

## 建议实施顺序

### 第一批：直接改善首次成功路径

1. 替换长截图引导，落地其中一个 demo 对应的信息结构。
2. 工作区空状态增加三个可用示例，带入任务草稿。
3. 回答底部展示明确的成果卡片和下载操作。
4. 将产品交付规则同步给 Agent，避免生成错误的 UI 操作指引。

### 第二批：完善结果查看和诊断信息

1. HTML 提供隔离的成品预览与源码切换；保持适当沙箱限制，避免用户生成内容访问宿主页。
2. CSV 提供表格预览，保留源码/下载入口。
3. 用户 ID、会话 ID、原始工具调用和性能统计收进可展开详情。
4. 自动生成任务标题，统一会话与 ZIP 命名。

### 第三批：通过使用数据验证

建议观察首次访问到首次发送的耗时、首次任务提交率、首次任务完成率、完成后的预览/下载率、首次成果后的追问率，以及引导跳过率。指标应区分示例浏览和真实任务，不把模拟交互计作成功任务。

## 验收清单

- 首屏可直接理解能完成什么，并有一个明显的主动作。
- 示例从需求到成果完整可见，不需要阅读长日志。
- 320px、375px 和桌面宽度无横向溢出；短屏可正常滚动到操作入口。
- 键盘可切换示例、编辑任务、前后导航和结束引导，状态变化可被辅助技术感知。
- 跳过与关闭不提交任务；实际发送后使用真实执行状态。
- 任务失败时保留输入，解释下一步，提供重试；不展示虚假的已完成成果。
- Agent 的文件操作说明与真实页面一致，单文件和 ZIP 下载都可达。
- 新用户完成至少一个“输入 → 执行 → 预览/下载 → 追问修改”的闭环。

## 本次可用性测试摘要

测试环境为 Edge 无痕窗口、新访客工作区、默认模型 `ark:deepseek-v4.1-flash`。以下记录为当次观察，不保证后续版本相同。

| 测试 | 结果 |
| --- | --- |
| 创建中文 hello.txt，写入 UX-1028，验证并下载 | 文件预览与单文件下载成功；Agent 对下载入口的描述不准确 |
| Python 汇总销售并生成 CSV/HTML | 咖啡 360、茶 300、蛋糕 150，总额 810 元；CSV 内容核对正确；HTML 预览为源码 |
| 追加咖啡退货 2 件，每件 18 元 | 总额正确减为 774 元，报告标题更新，hello.txt 保留 |
| 刷新后新建同项目会话读取已有文件 | 正确找回 UX-1028、6 条记录、774 元与报告标题 |
| 选择 Excalidraw 技能生成四节点流程图 | 源文件、PNG、SVG 生成；PNG 中文与箭头目视正常；ZIP 到达浏览器下载列表 |

站内性能面板前两轮耗时约 3.9 秒、6.5 秒，首输出约 0.92 秒、0.60 秒；这不是浏览器端完整等待时间。本次未做多用户隔离安全验证、移动设备实测或大规模任务稳定性测试。
