# 知识文档写作规则

- 知识文档供 AI 定位代码使用：先通过 `index.md` 找到功能模块，再通过知识文档的 `###` 小节匹配用户意图，最后阅读对应代码。
- 每个 `###` 小节只保留一句有意义的标题和关键代码入口。标题可略长，应说明处理对象、动作或关键条件；不添加解释段落、字段清单、实现代码、示例、表格、流程图或测试列表。
- 每篇聚焦一个功能模块，可用 `##` 按配置来源、依赖装配、执行流程等检索角度分组。不引用或链接其他文档，避免额外阅读的 token 开销。
- 代码入口保留文件路径和函数或方法签名，不写行号。使用业界通用术语和自然表达。
- `index.md` 仅作为目录，按 `关键词1、关键词2:文档路径` 添加条目。冒号前最多 8 个有区分度的关键词，用顿号分隔，覆盖主题、配置、依赖装配、关键步骤和持久化等不同检索角度，避免堆叠重复近义词；冒号后只写文档路径。
